# Digest — полезна ли сводка

Набор из `tech_plan.md` §10: десять сводок, оценка владельца 1–5. Здесь только
инструмент, который эти сводки достаёт, — оценку ставит владелец.

```
just eval-digest
```

## Какой режим воспроизводится

Тот же, что у воркера: решение по каждому слоту принимается в момент открытия
его окна, в таймзоне владельца, теми же функциями сбора и той же сборкой текста
(`core/digest`). Одна отправка на слот в сутки. Модель не зовётся ни разу,
потому что её не зовёт и прод (ADR-0013, ось 4).

## Чего повтор **не** воспроизводит

Это важнее того, что воспроизводит:

- **нажатий.** Дела никто не закрывает, петли никто не откладывает. Значит,
  это верхняя граница содержания сводки, а не то, что владелец увидел бы:
  в жизни список дел таял бы день ото дня;
- **бюджета и паузы.** Обе считаются по журналу касаний, которого за прошедшие
  дни не существует. Повтор считает, что бюджет цел и тишины нет;
- **накопления.** Всё считается по сегодняшнему состоянию базы: записи,
  размеченные позже, выглядят так, будто были размечены сразу;
- **случайности.** Всплывание в проде выбирает запись случайно, здесь берётся
  первая — иначе два прогона по одному архиву дали бы разные числа.

Ничего не пишет: ни строки в журнал касаний, ни сообщения в Telegram.

## Что он уже нашёл

Первый прогон 19 августа 2026 по живому архиву (39 записей, четыре дня) нашёл
три дыры, ни одну из которых не поймал бы модульный тест:

1. вечерний разбор повторял одну и ту же пачку из трёх записей **каждый вечер**;
2. утренняя сводка уходила, состоя целиком из строки «Со вчера ждут разбора: 2»;
3. недельное ревью срабатывало на архиве в один день, хотя `/status` обещает
   владельцу, что оно ждёт неделю.

Все три закрыты, каждая под тестом в `tests/test_digest_replay_findings.py`.
