# Eval · поиск по архиву

**Без числа отсюда Фаза 2 не закрыта.** Так записано в плане, и это
единственная защита от «вроде находит».

**Что меряем:** recall@5 — доля вопросов, у которых нужная запись попала
в первую пятёрку, — и MRR, среднее от 1/позиции первой нужной записи.
Плюс recall@5 **по каждому каналу отдельно**.

**Зачем поканальные числа.** Веса RRF стартовали равными (1/1/1). Это не
результат замера, а единственное стартовое положение, которое потом можно
опровергнуть. Опровергают его именно эти три числа: канал, у которого recall
близок к нулю на всём наборе, свой вес не отрабатывает. Без разбивки любая
правка веса — предпочтение, выданное за вывод.

## Правила

- **Набор размечает владелец, не модель.** Иначе меряется модель моделью.
- Вопросы — настоящие: те, с которыми реально придёшь в архив через полгода.
  «Что я решил про эмбеддинги» — вопрос. «Найди слово PGVector» — не вопрос,
  это проверка полнотекста, и она уже есть в тестах.
- Пятьдесят вопросов. Меньше — шум, больше — не размечается за вечер.
- Результат каждого прогона сохраняется в `results/`. Ухудшение — блокер мержа.

## Формат

Одна строка `dataset.jsonl` — один вопрос:

```json
{"question": "что я решил про размерность эмбеддингов", "relevant_entry_ids": [31], "note": "запись про фазу два"}
```

- `relevant_entry_ids` — **список**, не одно число. «Что я думал про поиск» —
  законный вопрос с четырьмя правильными ответами, и требовать от него ровно
  одного значило бы считать три верных попадания ошибками. Список из одного
  элемента — нормально.
- `note` необязательна и нужна только вам: через месяц «почему тут именно эти
  записи» вспоминается плохо.
- Строки, начинающиеся с `//`, пропускаются — ими удобно делить набор на темы.

## Как собрать

1. Открыть архив и выписать вопросы, которые вы бы задали, **не глядя
   на ответы**. Это важнее всего: вопрос, придуманный по записи, всегда
   находится, потому что содержит её слова.
2. Для каждого вопроса найти записи, которые на него отвечают:

```sql
SELECT e.id, coalesce(t.text, e.raw_text)
FROM entries e
LEFT JOIN LATERAL (
  SELECT text FROM transcripts WHERE source_entry_id = e.id ORDER BY id DESC LIMIT 1
) t ON true
ORDER BY e.id;
```

3. Записать строки в `dataset.jsonl`.

## Как прогнать

```
just eval-retrieval
uv run python -m evals.retrieval.run --k 10
```

Прогон ходит в модель эмбеддингов за вектором каждого вопроса: пятьдесят
вопросов — это доли цента.

## Чего этот eval не меряет

- **Скорость.** Она видна на живых запросах и на таком объёме не проблема.
- **Качество резки.** Длинная запись в архиве пока одна; когда их станет
  много, сюда добавится вопрос, ответ на который лежит в середине длинной
  записи, — сейчас такой вопрос проверял бы выдумку.
- **Приватные записи.** У них нет одного канала из трёх (инвариант 5), и это
  осознанная цена ADR-0002, а не то, что можно улучшить настройкой.
- **768 против 1536.** Это отдельный вопрос к этому же набору: прогнать,
  поменять размерность, прогнать снова. Замер сохранности структуры
  (18.08.2026) говорит, что разницы не будет, но recall он не мерил.
