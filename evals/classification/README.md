# Eval · разметка записей

**Без числа отсюда Фаза 3 не закрыта.** Так записано в плане, и это
единственная защита от «вроде правильно определяет».

**Что меряем:**

| число | на какой вопрос отвечает |
|---|---|
| точность | часто ли модель права |
| точность с учётом второй версии | помогает ли «две гипотезы» — то есть стоит ли вечерний разбор своего времени |
| **доля ошибок среди «уверен»** | можно ли верить слову «уверен» |
| матрица ошибок | в какую сторону модель путается |

Третье число важнее первого. Состояние считается по согласию двух прогонов
([ADR-0011](../../docs/adr/0011-annotation-types-state-and-topics.md)),
а согласие меряет **устойчивость, а не правоту**: два прогона могут
согласованно ошибаться. Если доля ошибок среди «уверен» заметно выше нуля,
значит либо промпт плохо разводит типы, либо двух прогонов мало.

## Правила

- **Набор размечает владелец, не модель.** Иначе меряется модель моделью.
- Размечать **не глядя на ответ модели**. Увидев её версию, согласиться легко —
  и набор начнёт мерить сам себя.
- Сто записей. Меньше — шум на девяти типах: на каждый тип придётся по десятку.
- Спорную запись размечать всё равно, а сомнение писать в `note`. Записи,
  которых нет в наборе, не мерят ничего; записи со спорной меткой мерят
  как минимум согласие с вами.
- Результат каждого прогона сохраняется в `results/`. Ухудшение — блокер мержа.

## Формат

Одна строка `dataset.jsonl` — одна запись:

```json
{"entry_id": 26, "type": "task", "note": "напоминание про собственное действие"}
```

- `entry_id` — номер записи в базе. **Текста здесь нет и не должно быть:**
  архив в репозиторий не уходит ([ADR-0002](../../docs/adr/0002-privacy.md)),
  а номер и тип его не раскрывают.
- `type` — одно из девяти значений: `thought` · `task` · `event` · `loop` ·
  `decision` · `error` · `insight` · `refusal` · `noise`. Определения — в
  `core/enrich/prompt.py`, там же, где их видит модель.
- `note` необязательна и нужна только вам.
- Строки, начинающиеся с `//`, пропускаются.

## Как размечать

1. Выписать записи с текстами:

```sql
SELECT e.id, coalesce(t.text, e.raw_text)
FROM entries e
LEFT JOIN LATERAL (
  SELECT text FROM transcripts WHERE source_entry_id = e.id ORDER BY id DESC LIMIT 1
) t ON true
WHERE coalesce(t.text, e.raw_text) IS NOT NULL
ORDER BY e.id;
```

2. По каждой ответить себе: **что это за запись** — не «что с ней делать»,
   а чем она является. Подсказки на границах:

| граница | правило |
|---|---|
| задача / событие | «сделаю сам» — task, «случится само» — event |
| мысль / понимание | insight там, где появилось новое знание («понял, что...») |
| мысль / открытый вопрос | loop — если вы собирались вернуться и не вернулись |
| решение / отказ | refusal — только про «решил НЕ делать» |
| что угодно / служебное | noise — если смысла в записи нет вовсе |

3. Записать строки в `dataset.jsonl`.

## Как прогнать

```bash
just eval-classification
just eval-classification --model gemini-3.1-flash-lite
```

Второй командой сравниваются модели на одном наборе — **это и есть способ
выбрать дешёвый тир**. Разница в цене между кандидатами на 600 записях
в месяц — пять центов, так что решает только это число.

Прогон ничего не пишет в `annotations`: набор гоняется по многу раз, и архив
от этого замусориваться не должен. Строку в `llm_calls` он пишет — прогон
стоит денег, и они должны быть видны там же, где остальные.
