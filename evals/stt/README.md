# Eval · расшифровка голоса

Первый eval проекта. Он первый именно потому, что для него не нужен архив:
двадцать голосовых можно наговорить за вечер.

**Что меряем:** WER (word error rate) на своей речи — русский вперемешку
с английскими терминами. Ни один публичный бенчмарк этот случай не отражает,
лидерборды считаются в основном по английскому.

**Зачем:** [ADR-0009](../../docs/adr/0009-stt-provider-and-http-client.md)
поставил провайдера по умолчанию **до** замера — иначе не на чем было бы
записать корпус. Этот прогон закрывает долг: показывает, правильный ли выбор
сделан, и во сколько обойдётся правильный.

## Правила

- **Размечает владелец, не модель.** Иначе меряется модель моделью.
- Двадцать записей достаточно, чтобы увидеть разницу в несколько процентов.
  Начинать с малого лучше, чем не начинать.
- Записи — настоящие, из обычного дня: на ходу, с улицы, с терминами,
  с оговорками. Дикторская речь в тихой комнате меряет не то.
- Результат прогона сохраняется. Ухудшение — блокер мержа.

## Как собрать корпус

1. Наговорить боту двадцать обычных голосовых. Они уже сохранятся
   в `var/audio/` вместе с расшифровкой.
2. Скопировать файлы в `evals/stt/audio/`.
3. Для каждого написать в `dataset.jsonl` строку с **эталонной** расшифровкой —
   тем, что было сказано на самом деле:

```json
{"audio": "audio/111_42.oga", "reference": "надо переписать ретривал на гибридный поиск"}
```

Эталон пишется дословно: со словами-паразитами, но без пунктуации и заглавных
букв — их всё равно не с чем сравнивать. Числа — словами, как произнесены.

## Как прогнать

```
uv run python -m evals.stt.run                      # провайдер из .env
uv run python -m evals.stt.run --model gemini-2.5-flash
```

Скрипт печатает WER по каждой записи и общий, а полный результат кладёт
в `evals/stt/results/`. Сравнение двух провайдеров — два прогона.

Прогон стоит денег: двадцать записей по минуте это около $0.01 на Gemini
и около $0.07 на Scribe. Дешевле любого решения, принятого на глаз.

## Чего этот eval не меряет

- Скорость. Она видна по `transcripts.latency_ms` на реальных записях.
- Качество на длинном аудио: голосовые в корпусе короткие, а потолок — 15 минут.
- Пунктуацию и форматирование. Для поиска и разметки они не важны.
