# Brain

Персональный ассистент с памятью: принимает мысли голосом и текстом в Telegram,
размечает их дешёвой моделью, хранит в Postgres и умеет искать по архиву.
Один пользователь, один сервер, никакой мультиарендности.

Главное правило проекта: **скорость важна, но не ценой понимания**. Через полгода
владелец должен уметь открыть любой модуль и объяснить голосом, что тот делает
и почему сделан так. Код, который этому мешает, — плохой код, даже если работает.

## Инварианты

Нарушать нельзя. Проверяются на ревью.

1. Адаптеры (`api/`, `adapters/`) не обращаются к БД напрямую — только через сервисы `core/`.
2. Прямых вызовов SDK провайдера вне `core/llm` (и `core/stt` для аудио) нет.
3. Таблица `entries` только на вставку. UPDATE и DELETE отозваны на уровне прав БД.
   Смена состояния — строкой в `entry_overrides`.
4. Любая производная запись хранит `source_entry_id`.
5. Записи с `is_private=true` никогда не уходят наружу: ни в LLM, ни в эмбеддинги,
   ни в STT, ни в Notion. Проверка живёт в `core/llm`, `core/stt` и `integrations`,
   а не в вызывающем коде.
6. Никаких секретов в коде. Только переменные окружения через `brain.config`.
7. Запись в `entries` и задание в очередь пишутся **одной транзакцией**.
   Ради этого очередь и живёт в Postgres.
8. Связи между записями считаются векторной близостью, **без вызова модели**.

## Структура

```
src/brain/
  config.py          единственное место, где читается окружение
  api/               HTTP. До Фазы 5 здесь только /health
  storage/           движок, модели, миграции Alembic
  core/              ingest · stt · enrich · memory · retrieval · scheduler · digest · llm
  adapters/telegram/ бот (Фаза 1)
  integrations/      calendar · notion
tests/               быстрые тесты по умолчанию; живая БД — под маркером integration
docs/adr/            решения. Пишет их владелец, не Claude
```

## Команды

```
just up          поднять Postgres (единственный сервис в compose)
just dev         запустить API на :8000
just test        быстрые тесты — без БД и сети
just test-all    все тесты, включая integration (нужен поднятый Postgres)
just lint        ruff format --check + ruff check
just typecheck   mypy
just check       всё, что гоняет CI
just migrate     alembic upgrade head
just migration "описание"   новая миграция
```

## Стиль кода

- Комментарии и документация — по-русски. Объясняют **почему**, а не что: «что»
  видно из кода, «почему» через полгода не восстанавливается.
- Типы обязательны везде: mypy в режиме strict.
- Модуль вырос и делает несколько вещей — разделить, не дожидаясь просьбы.

## Стиль коммитов

Заголовок в повелительном наклонении, до 72 символов, без префиксов вида `feat:`.
Тело — зачем менялось, а не что менялось. Одна логическая правка — один коммит.

## Чего нельзя

Часть этого закрыта хуками в `.claude/settings.json` и просто не выполнится.

- **Коммитить и пушить.** Это делает владелец, руками, прочитав дифф.
- **Откатывать миграции** (`alembic downgrade`). Нужен откат — новая миграция вперёд.
- **Сносить том с базой** (`docker compose down -v`).
- **`rm -rf`.**
- **Писать секреты в файлы.** Только `.env`, которого нет в git.
- **Добавлять зависимость без ADR.**
- **Править применённую миграцию задним числом.** Только новая поверх.
- **Заканчивать сессию с красными тестами** — Stop-хук не даст.
- **Использовать `--dangerously-skip-permissions`.** Ни разу.

## Перед изменением архитектуры

Прочитать `docs/adr/` — семь решений с контекстом, вариантами и ценой:
стек · приватность · схема и append-only · абстракция LLM · очередь на Postgres ·
ретривал · STT. Решение уже принятое не переспорить в чате: несогласен —
пишется новый ADR, старый не переписывается.

Планы и рамки проекта: `docs/tech_plan.md`, `docs/vision.md`, `docs/status.md`.
Новая фича, которой нет в `vision.md`, в код не попадает.
