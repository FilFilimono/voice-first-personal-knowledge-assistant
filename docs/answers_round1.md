## НОВЫЕ ПРИНЦИПЫ (добавить в оба документа)

### П1. Начинаем с минимума, растём по факту боли

Не закладываем запас «на будущее». Берём самый дешёвый работающий вариант, упираемся — увеличиваем. Касается сервера, моделей, индексов, всего.

Следствие: **самый младший тариф VPS** (~4GB RAM). Parakeet в ONNX INT8 туда помещается, расшифровка идёт медленнее — 2-минутное голосовое за 1–3 минуты. Для асинхронной схемы «ack → результат отдельным сообщением» приемлемо. Упрёмся — перейдём на старший тариф одной кнопкой.

### П2. Экономия токенов — требование, а не оптимизация

1. **Не вызывать модель там, где хватает кода.** Парсинг времени, определение URL, дедупликация, определение языка — код, не LLM.
2. **Векторы вместо модели.** Поиск связей — чистая векторная близость, ноль вызовов LLM.
3. **Маршрутизация обязательна** (см. п.20).
4. **Батчинг.** Вечерняя разметка накопленных записей — одним вызовом на пачку. Плюс батч-API даёт скидку 50% на такие офлайн-задачи.
5. **Кэширование системного промпта.** Попадание в кэш стоит порядка 10% от обычной входной цены.
6. **Учёт с первого дня.** Таблица `llm_calls`: модель, токены, стоимость, назначение.
7. **Бюджетный потолок** с деградацией (см. п.20).

**Важное отрезвление:** при объёме ~20 записей в день разница между самым дешёвым и удобным провайдером — порядка тридцати центов в месяц. Экономия живёт в архитектуре (меньше вызовов, кэш, батчи), а не в выборе провайдера. Не тратить время на охоту за копеечной разницей в прайсе.

## A. ПРОТИВОРЕЧИЯ

### 1. Шифрование приватных записей → без приложенческого шифрования

Замечание верное: `tsv` рядом с зашифрованным текстом — театр. Но и полное шифрование не проходит: оно требует ключа вне сервера, а ключ, вводимый руками при старте, ломает автоподъём после перезагрузки — утренняя сводка не придёт.

**Решение:**
- Приватность = запись **никогда не уходит во внешний API**. Проверка в `core/llm`, не у вызывающего кода.
- Приватные записи: `tsv` есть (поиск по словам работает), `embedding` NULL, аннотаций нет.
- Защита данных: шифрование диска VPS + **шифрованные бэкапы, ключ хранится не на сервере**.
- Принимаемый риск: компрометация сервера = доступ ко всему. Зафиксировать явно в ADR-0002.

Приложенческое шифрование можно добавить позже, если модель угроз изменится.

### 2. entries только INSERT → append-only оверрайды

Принимается `entry_overrides` (entry_id, action, payload, created_at). Актуальное состояние — последняя строка. Инвариант 3 остаётся в силе.

**Ретроактивная приватность разрешена**, но честно: при переводе в приватные удаляем `chunks.embedding` и аннотации, и бот прямо говорит «текст уже отправлялся во внешнюю модель ранее». Запрещать переход нельзя — человек не всегда понимает в момент записи, что записал.

### 3. Утренняя сводка → отдельная категория, молчание её не касается

Утренняя сводка — про сегодняшний день (календарь, обещания), а не про архив. Работает с первого дня.

Молчание первых двух недель касается только: всплывания старого, наблюдений, предложенных связей.

Бюджет 3 касания: дневное + вечернее + одно резервное. Утренняя сводка вне бюджета.

### 4. Порядок фаз → источник истины `tech_plan §8`, с одной правкой

`vision §15` переписать под `tech_plan §8`.

**Правка:** базовые напоминания (по времени, без календаря) переносятся в **Фазу 1**. Дёшево — таблица плюс задание в планировщике — и даёт ежедневную пользу сразу. Интеграция с Google Calendar остаётся Фазой 5.

Notion — Фаза 6. До разметки записей витрина будет свалкой, а не витриной.

### 5. Адаптация к загруженности → деградирует до «день не забит»

Фазы не переставляем. До Фазы 5 календаря нет, правило «день забит → дневное касание отменяется» просто не срабатывает. Остальные условия (нечего разбирать → молчим) работают и без календаря.

### 6. Дыры в схеме → все три добавления подтверждены

- `entry_topics` (entry_id, topic_id, confidence) — да
- `rules` (процедурная память) — да. Попадают в промпты отдельным блоком системного сообщения, собираемым в `core/llm`. Редактируются мной через бота.
- `entries.meta jsonb` — да. Для `source=forward`: откуда, автор, дата исходного сообщения.

### 7. ARQ + APScheduler → выкинуть APScheduler

Дублирование. У ARQ есть cron-задания, воркер один. Минус зависимость, минус ADR.

### 8. Долговечность записи → инвариант

Порядок жёсткий: INSERT в `entries` (транзакция закрыта) → только потом задание в очередь, и в задании **только `entry_id`**, не содержимое. Плюс периодический sweep: записи без аннотаций старше N минут переставляются в очередь.

Записать как инвариант 7 в `tech_plan §1`.

## B. МЕХАНИКА

### 9. Пометка «приватно» → режим-переключатель + кнопка

- `/private on` — все следующие записи приватные до `/private off`. Работает и для голоса.
- Кнопка «сделать приватной» в ack-сообщении — ретроактивно (см. п.2).
- Дефолт — не приватно.

Отдельный топик в Telegram отклонён: топики есть только в группах, лишняя сущность.

### 10. Модель подтверждений → enum вместо числа

Числовая самооценка у моделей плохо калибрована. Модель возвращает enum: `уверен` / `две гипотезы` / `не понял`.

| Состояние | Внешний эффект | Действие |
|---|---|---|
| уверен | нет | молча сохранить + кнопка «не туда» |
| любое | да (календарь, напоминание) | спросить сразу |
| две гипотезы | нет | в вечерний пакет |
| не понял | нет | в вечерний пакет |

### 11. Открытые петли

- Создаётся LLM, но с явным подтверждением при записи («это открытый вопрос?»)
- Выбор: старейшая среди не спрошенных за 14 дней
- «Ещё думаю» → сдвиг на 14 дней
- Минимум 3 дня между вопросами по одной петле
- После 3-го «ещё думаю» вопрос меняется на «закрыть или переформулировать?» — петля перестаёт быть раздражителем

### 12. Всплывание старого → адаптивный порог

- Порог: `max(14 дней, возраст старейших 25% архива)`. Пока архив младше 60 дней, механизм работает на том, что есть, а не молчит месяцами.
- Приватные **включены** — ничего наружу не уходит, это мой архив и мой бот.
- Исключаем записи короче 100 символов.
- Одна и та же запись не всплывает чаще раза в 90 дней.

### 13. Связи и противоречия → **без LLM в основном пути**

Ключевое решение по экономии.

- **Связи ищутся чистой векторной близостью.** Ноль вызовов модели. Top-5 кандидатов, порог косинуса ~0.75 (калибруется на реальных данных), показываем максимум 2.
- **Противоречия:** вызов модели только если есть кандидат с близостью выше высокого порога (~0.85). Редкий случай — единицы раз в неделю, не 20 раз в день. Дешёвая модель, один вызов.
- Противоречия проверяем только для типов `thought` и `decision`.

Зафиксировать как осознанное решение, а не как случайность.

### 14. Темы → сначала попытка попасть в существующую

LLM обязана сначала попробовать существующую тему (top-K по эмбеддингу названий тем). Новая тема — только с явным обоснованием.

Мягкий потолок ~30 тем. При превышении — в недельном ревью предложение слить похожие.

### 15. facts (триплеты) → отложить за Фазу 6

Нормализация сущностей («Маша» = «Мария Иванова» = «она») — отдельный проект, съест недели и даст шум.

Пока: `annotations` + поиск по записям. «Что я знаю про X» делается через retrieval.

Таблицу `facts` из схемы Фазы 3 убрать.

### 16. Ретривал и русский

- Чанк = вся запись, если <1500 символов. Длиннее — по абзацам и паузам, перекрытие ~15%.
- **pg_trgm третьим каналом в RRF.** Русский snowball без лемматизации плохо берёт словоформы, а смесь с английскими терминами ломает статистику BM25. Триграммы это частично компенсируют.
- Модель эмбеддингов выбирается на шаге 5.2, размерность фиксируется в ADR-0006.
- **🔴-тема.** Показать варианты с трейдофами, не выбирать молча.

### 17. Eval ретривала без корпуса → сдвинуть

- **STT-eval делаем сразу** (Фаза 1): 20 голосовых, ручная разметка, WER. Корпус не нужен.
- **Retrieval-eval сдвигается на конец Фазы 2 / начало Фазы 3**, когда наберётся 100–150 записей за первую неделю пользования.
- **Импорта нет.** Стартуем с пустого архива, наполняем ежедневным использованием. Apple Notes и Reminders отпадают — у них нет серверного API, писать и читать с VPS нельзя. Напоминания у нас свои, внутри бота, с Фазы 1.

### 18. Кнопка паузы → гасит только инициативные

Напоминания, календарь, контекст перед событием продолжают работать. Система не молчит о том, о чём я сам просил. То же для «сегодня выходной».

### 19. Журнал решений

- `check_at` предлагает LLM (дефолт 90 дней), я могу переопределить голосом при записи («проверь через месяц»).
- Проверка исхода — **заказанная категория**, вне бюджета касаний.

### 20. Маршрутизация моделей

**Дешёвый тир: Gemini Flash-Lite.**
**Дорогой тир: Claude Sonnet.**

| Задача | Модель |
|---|---|
| Классификация типа записи, теги, темы | дешёвая |
| Проверка противоречий | дешёвая |
| Сборка утренней сводки | дешёвая (данные готовы, нужна формулировка) |
| Вечерний разбор | дешёвая |
| Недельное ревью | дорогая |
| Диалог с архивом, сократический режим, Фейнман | дорогая |
| Поиск связей | **без модели** |

**Отклонено и почему:**
- **DeepSeek V4 Flash** — самый дешёвый по прайсу, но хостится в Китае. В систему идёт личный дневник; экономия порядка тридцати центов в месяц не стоит этого. Плюс анонсирована пиковая тарификация, удваивающая цену в определённые часы, что ломает предсказуемость бюджета.
- **OpenRouter** — удобен для переключения, но берёт комиссию и прячет механику вызовов. Прямые SDK двух провайдеров за собственной абстракцией дешевле и дают нужный навык.

**Замер вместо прайса:** выбор дешёвой модели подтверждается eval на русской классификации в Фазе 3. Разница в цене копеечная, разница в качестве может быть заметной.

**При достижении бюджетного потолка:** enrich переводится в отложенную очередь (записи сохраняются, разметка ждёт), дорогие режимы отключаются, приходит уведомление. Захват не ломается никогда.

⏳ Цена Claude Sonnet: вводный тариф $2/M действует до 31 августа 2026, с 1 сентября $3/M. Заложить в расчёт.

## C. ИНФРАСТРУКТУРА

### 21. Telegram → polling, два бота, whitelist

- **Polling.** Не нужен домен, TLS и Caddy — минус статья расходов. Плюс Telegram хранит апдейты ~24 часа, что прямо поддерживает «ни одна запись не потеряна».
- **Два бота:** dev и prod, разные токены. Бесплатно, избавляет от порчи реальных данных при отладке.
- Доступ: whitelist `TELEGRAM_ALLOWED_USER_IDS` в `.env`, всё остальное игнорируется молча.

### 22. user_id в схеме → не добавлять

YAGNI, один пользователь. Отказ зафиксировать в ADR-0003 — если однажды понадобится, будет понятно, почему решили так.

### 23. Голос

- **ffmpeg** — добавить в образ, обязателен (Telegram отдаёт OGG/Opus).
- **Максимум 15 минут** на голосовое. Длиннее — режем по паузам.
- **Скорость на 2 vCPU** — измерить на шаге 5.2 на реальном железе. Если 2-минутное голосовое обрабатывается дольше 3 минут — либо старший тариф, либо STT через API. Решение по факту замера.
- **ONNX INT8 сборка Parakeet TDT 0.6B v3** — проверить существование и способ загрузки. Если тянет полный NeMo и torch — бюджет RAM ломается, тогда план Б: STT через API. **Блокер Фазы 1, проверять первым.**

### 24. Google Calendar

- OAuth desktop-flow один раз, refresh token в `.env`.
- **Читаем** все календари.
- **Пишем** только в отдельный календарь «Brain» — событие, созданное ботом, всегда отличимо и удаляется одним движением.
- Узнаём о событии **опросом раз в 5 минут**. Push-нотификации требуют домена — не берём.

### 25. Notion → одна база + страницы ревью

- База «Записи»: дата, тип, темы, текст, ссылка на исходную запись.
- Отдельные страницы для недельных ревью.
- Синхронизируем **только записи с аннотациями** (то есть после Фазы 3).
- **Приватные — никогда.** Notion это третья сторона.

### 26. Деплой и бэкапы

- **Код:** пушу я в GitHub, на сервере `git pull && docker compose up -d --build`. Позже — GitHub Actions.
- **Миграции:** отдельной командой в том же шаге, **не автоматически при старте контейнера.** Автомиграция на старте — классическая мина.
- **Бэкапы:** `pg_dump` + gzip раз в сутки в объектное хранилище с бесплатным тарифом. Годы текста сжимаются в десятки мегабайт. Шифрование бэкапа ключом, который лежит не на сервере.
- **Аудио:** не бэкапим, удаляем через 30 дней.
- **Проверка восстановления:** раз в месяц, поднимаем дамп локально. Повторяющееся событие в календаре.

### 27. API-ключи → два, оба платные

Подписка Max покрывает Claude Code, но **не** вызовы модели из бота.

Нужны:
- **Google AI Studio** — ключ для Gemini Flash-Lite (дешёвый тир)
- **Anthropic Console** — ключ с балансом для Claude Sonnet (дорогой тир)

Это и есть $1.5–2.5/мес. Два реальных провайдера — не абстрактное «что-нибудь»: интерфейс `core/llm` проектируется под две конкретные реализации, что и делает его действительно заменяемым.

## D. ПРОЦЕСС

### 28. Тесты → разделить

- **Быстрые unit** (без БД, LLM замокан) — в хуке `Stop`. Отрабатывают за секунды.
- **Интеграционные** (живой Postgres из compose) — по команде и в CI.
- **Evals** — отдельно, см. п.29.

### 29. Evals в CI → только детерминированные

- Автоматически в CI: STT WER, retrieval recall@k, точность классификации. Дёшево, стабильно.
- LLM-судья: только вручную через `/eval`, перед мержем существенных изменений промптов. Он и дорогой, и шумный.
