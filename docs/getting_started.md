# Старт с нуля: Claude Code

Инструкция для macOS. Данные проверены 12 августа 2026 (Claude Code ~2.1.224). ⏳ Способ установки менялся за последний год — если команда не сработает, смотри https://code.claude.com/docs/en/setup

---

## Шаг 1 · Установка

Открой Терминал (Cmd+Space → «Терминал») и вставь:

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

Это нативный установщик — Node.js не нужен, обновляется сам. Через минуту закрой терминал и открой заново, потом проверь:

```bash
claude --version
```

Если команда не найдена — путь не подхватился:

```bash
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc
```

Диагностика при любых проблемах: `claude doctor`

## Шаг 4 · Минимум команд, который надо знать

| Команда | Что делает |
|---|---|
| `/help` | список всех команд |
| **Shift+Tab** | переключение режимов, включая **plan mode** — Claude сначала показывает план, ничего не делая |
| `Esc` | прервать Claude на середине |
| `/clear` | новый чистый контекст. Жать между задачами |
| `/init` | сгенерировать черновик CLAUDE.md по репозиторию |
| `/doctor` | диагностика установки |
| `@путь/файл` | подставить файл в сообщение |
| `!команда` | выполнить bash-команду напрямую |
| `Ctrl+C` дважды | выйти |

**Plan mode — главное.** Всё, что трогает больше одного файла, запускается через него. Claude показывает план, ты правишь, потом соглашаешься.

## Шаг 5 · Сессия 1: подготовка (кода не пишем)

Копируй промпты по одному. После каждого читай ответ, не гони дальше молча.

### 5.1. Дать контекст и найти дыры

```
Прочитай @docs/vision.md и @docs/tech_plan.md полностью.
Не пиши код. Не создавай файлы.
Задай мне вопросы по всему, что в этих документах неоднозначно,
противоречиво или недоопределено для реализации.
Отсортируй вопросы по важности.
```

Отвечай на вопросы. Это самая полезная часть сессии — здесь всплывут дыры, которые иначе вылезут через неделю в коде.

### 5.2. Проверить версии

```
Через MCP-документацию или веб проверь актуальные версии на сегодня:
Python, aiogram, FastAPI, Pydantic, SQLAlchemy, Alembic, pgvector,
ARQ, APScheduler, ruff, mypy, uv.
Отдельно: доступные модели Anthropic и цены за токен,
модели эмбеддингов с поддержкой русского и их цены.
Отдельно: не вышло ли после Parakeet TDT 0.6B v3 чего-то лучше для русского.

Сделай таблицу: что записано в плане / что актуально / что изменилось.
Не полагайся на память — только на проверенные источники, с ссылками.
```

### 5.3. Первое решение (ADR) — пишешь ты

```
Сгенерируй ШАБЛОН docs/adr/0001-stack.md.
Формат: Контекст / Варианты (2-3, с трейдофами) / Решение / Цена решения.
Раздел "Решение" оставь пустым — заполню я.
```

Заполняешь сам. Десять минут. Это твоя точка входа в проект.

### 5.4. CLAUDE.md

```
Составь CLAUDE.md по разделу 5.2 из @docs/tech_plan.md.
Максимум 120 строк. Инварианты из раздела 1 — списком, явно.
Не пересказывай vision.md, дай на него ссылку.
```

Прочитай и поправь под себя. Это файл, который Claude читает каждую сессию.

### 5.5. Хуки

```
Создай .claude/settings.json с хуками по разделу 5.3 из @docs/tech_plan.md.
Проверь актуальный синтаксис хуков по документации Claude Code,
не по памяти. Объясни каждый хук одной строкой.
```

**Важно:** там есть хук, запрещающий Claude коммитить в main. Это намеренно.

### 5.6. Скелет проекта

Переключись в plan mode (Shift+Tab), потом:

```
Собери скелет по разделу 4 из @docs/tech_plan.md:
pyproject.toml (uv), justfile, docker-compose.yml с postgres+pgvector и redis,
структуру папок src/brain/, пустую первую миграцию Alembic,
FastAPI с эндпоинтом /health, .gitignore, .env.example.
Кода бизнес-логики не пиши.
```

Сначала прочитай план, потом запускай.

### 5.7. Проверка и коммит

```bash
just up      # или docker compose up -d
curl localhost:8000/health
git add -A && git commit -m "chore: скелет проекта"
```

**На этом сессия 1 закончена.** `/clear`.

## Шаг 6 · Сессия 2: MCP-серверы

MCP — это внешние инструменты для Claude на время разработки. К самому боту отношения не имеют.

```bash
claude mcp add --help
```

Нужны три:
- **postgres** — чтобы Claude видел реальную схему БД, а не выдумывал таблицы
- **github** — issues и PR
- **документация библиотек** — актуальные API вместо памяти модели

Промпт:

```
Найди в актуальной документации Claude Code, как подключить MCP-серверы
для PostgreSQL, GitHub и документации библиотек.
Дай точные команды для моего случая. Ничего не выполняй — я запущу сам.
```

Проверка: `/mcp` внутри сессии покажет подключённое.

## Шаг 7 · Ежедневный ритм

**Начало работы:**
```bash
cd ~/projects/brain && claude
```
```
/session-start
```
(команду сделаем на второй неделе; пока просто спроси «что сделано, что дальше по плану»)

**Одна задача:**
1. `git checkout -b feature/название`
2. Shift+Tab → plan mode
3. Пишешь задачу + список тест-кейсов в 5 строк
4. Читаешь план, правишь, запускаешь
5. Claude пишет, коммитит на ветку
6. `/explain-diff` — читаешь, задаёшь вопросы
7. Мержишь сам
8. `/clear`

**Не понял что-то — спрашивай сразу, в той же сессии.** Контекст есть, ответ будет точный. Через день его уже не будет.

## Чего не делать

- **Никогда `--dangerously-skip-permissions`.** Прямой путь к проекту, который ты не понимаешь.
- Не работать в одной сессии весь день. Задача — `/clear` — задача.
- Не мержить дифф, который не смотрел.
- Не добавлять фичи, которых нет в `vision.md`. Новая идея → в архив, не в код.
- Не гнать вперёд, если Claude задал вопрос и ты ответил «делай как считаешь». Это и есть вайб-кодинг.

---

## Если что-то сломалось

| Симптом | Что делать |
|---|---|
| `claude` не найден | `claude doctor`, проверь PATH |
| Claude «забыл» контекст | контекст сжался — `/clear` и начни задачу заново |
| Отвечает не по делу | слишком длинная сессия, `/clear` |
| Правит не те файлы | не был включён plan mode |
| Ставит устаревшие версии | не подключён MCP документации |
