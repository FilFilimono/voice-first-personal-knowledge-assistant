# ADR-0001 · Стек

**Статус:** принято · **Дата:** 15 августа 2026
**Связанные:** [0004](0004-llm-abstraction-and-routing.md) (LLM), [0005](0005-queue-on-postgres.md) (очередь), [0006](0006-retrieval.md) (ретривал), [0007](0007-stt.md) (STT)

## Контекст

Персональный ассистент на одного пользователя. Нагрузка — порядка двадцати записей в день. Хостинг — один VPS. Бюджет — €7–11 в месяц вместе с сервером.

Три условия задают выбор сильнее, чем технические требования:

1. **Критерий успеха — понимание, а не работоспособность.** Через полгода я должен уметь открыть любой модуль и объяснить голосом, что он делает и почему сделан так. Стек, который работает, но которого я не понимаю, считается провалом.
2. **Начинаем с минимума** (принцип 11 `vision.md`). Не закладываем запас на будущее: берём самый дешёвый работающий вариант, упираемся — увеличиваем.
3. **Сроков нет.** Экономия недели разработки не аргумент; экономия месяца непонимания — аргумент.

Нагрузка настолько мала, что *технические* характеристики почти всех кандидатов избыточны. Реальный критерий выбора — количество компонентов и прозрачность механики.

## Варианты с трейдофами

### Ось 1. Хранилище: одно или несколько

| Вариант | За | Против |
|---|---|---|
| **Postgres на всё** — реляционка, полнотекст, триграммы, вектора, очередь | один компонент, одна резервная копия, задание в очередь пишется в одной транзакции с записью, дешевле по RAM | pgvector медленнее выделенной векторной БД на больших объёмах; полнотекст в Postgres беднее Elastic |
| Postgres + Redis (очередь и кэш) | привычная связка, ARQ из коробки | +компонент, +память на 4 ГБ, транзакционная постановка задания невозможна, ARQ переведён в maintenance-only |
| Postgres + Qdrant/Pinecone | лучший векторный поиск | +компонент, +точка отказа, +ещё одна копия данных для консистентности — на десятках тысяч записей выигрыш не наблюдаем |

### Ось 2. Слой работы с LLM

| Вариант | За | Против |
|---|---|---|
| **Свой тонкий `core/llm`** | понимаю каждый вызов, приватность и учёт стоимости в одной точке | пишу ретраи, таймауты и structured output сам |
| LangChain / LlamaIndex | готовые цепочки, ретривал из коробки | абстракции чужие и текучие, пайплайн у нас специфический, а главное — я не понимаю, что внутри, что прямо противоречит критерию успеха |

### Ось 3. Развёртывание

| Вариант | За | Против |
|---|---|---|
| **Docker Compose, один VPS** | тот же файл локально и на сервере, читается целиком за минуту | нет HA, деплой = минута простоя |
| Kubernetes | масштабирование, самолечение | один сервис и один пользователь — оркестратор дороже оркестрируемого |
| PaaS (Railway/Fly) | ноль администрирования | дороже, меньше контроля, привязка к платформе |

### Ось 4. Мелкое, но не бесплатное

- **Python 3.13 против 3.12:** 3.12 ушла в security-only; все зависимости 3.13 поддерживают.
- **uv против poetry:** быстрее и предсказуемее резолвер; экосистема моложе.
- **aiogram против python-telegram-bot:** единственный зрелый async-фреймворк под наш async-стек.
- **ruff против black+flake8+isort:** один инструмент вместо трёх.

## Решение

| Слой | Выбор | Версия |
|---|---|---|
| Язык | Python | 3.13 |
| Бот | aiogram, polling, два бота (dev и prod, разные токены) | 3.30 |
| API-ядро | FastAPI + Pydantic v2 | 0.141.1 / 2.13.4 |
| ORM и миграции | SQLAlchemy + Alembic | 2.0.52 / 1.19.1 |
| БД | PostgreSQL + pgvector + pg_trgm | 17 / ≥0.8.2 |
| Очередь и расписание | pgqueuer поверх Postgres | 1.3.2 |
| LLM | свой `core/llm`, дешёвый тир Gemini Flash-Lite | — |
| STT | внешний API за интерфейсом `core/stt` | — |
| Эмбеддинги | Gemini Embedding, 768 измерений | — |
| Контейнеры | Docker + Compose | — |
| Хостинг | Hetzner CX23, 2 vCPU / 4 GB | €5.49/мес |
| Линт, типы, тесты, пакеты | ruff 0.16.2 · mypy 2.3.0 (strict на `core/`) · pytest · uv 0.12.3 | — |

**Правило версий:** пиним по реальному состоянию реестра пакетов, а не по памяти модели. Проверка — раз в квартал.

**Явно не берём:** Redis, ARQ, APScheduler, отдельную векторную БД, Kubernetes, LangChain/LlamaIndex, OpenRouter, вебхуки с доменом и TLS, мультиагентную архитектуру, локальный STT.

## Цена решения

- **Один VPS без резервирования.** Падение сервера = система не работает, деплой = минута простоя. Принято: это личный инструмент, не сервис.
- **Postgres как векторная БД** упрётся первым, если архив вырастет на порядки. Момент, когда это произойдёт, мы узнаем по латентности поиска, а не заранее — и это осознанный размен по принципу 11.
- **Отказ от LangChain — это работа.** Ретраи, таймауты, разбор structured output, поддержка двух SDK пишутся руками. Оплачено пониманием.
- **4 ГБ RAM закрывают дверь локальным моделям.** Любая своя модель (STT, эмбеддинги, LLM) требует более дорогого тарифа. Решение обратимо кнопкой, но не бесплатно.
- **Python 3.13 и uv** — молодая сторона экосистемы: изредка встречаются пакеты без колёс или с отставшей поддержкой.
- **Два бота вместо одного** — две записи в конфиге, два токена в секретах и обязанность помнить, какой запущен. Взамен — отладка не портит реальный архив.
- **Polling вместо вебхука** — постоянный исходящий трафик и задержка до секунды на доставке. Взамен нет домена, TLS и обратного прокси, а Telegram держит апдейты ~24 часа, что работает как страховка от потери записи.
