# ADR-0002 · Приватность

**Статус:** принято · **Дата:** 15 августа 2026
**Связанные:** [0003](0003-schema-and-append-only.md) (пишется в паре с этим), [0004](0004-llm-abstraction-and-routing.md) (точка проверки), [0007](0007-stt.md) (следствие для голоса)

---

## Контекст

В систему идёт личный дневник: мысли, решения, ошибки, разговоры. Часть записей я не хочу отдавать наружу ни при каких условиях — ни в LLM, ни в сервис расшифровки, ни в Notion.

Одновременно:

- Сервер — арендованный VPS. Физического контроля над диском нет.
- Бот должен подниматься сам после перезагрузки, иначе утренняя сводка не придёт, а система, которая молча умирает на неделю, бесполезна.
- Поиск по словам должен работать всегда, включая приватные записи. Архив, в котором часть записей не находится, перестаёт быть архивом.

Исходно в `vision.md` предполагалось шифровать приватные записи на уровне приложения. При проверке решение развалилось: рядом с зашифрованным текстом лежит `tsvector`, а `tsvector` — это и есть слова записи. Шифрование, которое хранит открытый список слов рядом с шифротекстом, защищает от чтения, но не от понимания.

## Варианты с трейдофами

| Вариант | За | Против |
|---|---|---|
| **Флаг `is_private` + шифрование диска VPS + шифрованные бэкапы с ключом вне сервера** — выбран | бот поднимается сам; полнотекстовый поиск работает по всему архиву; сложность нулевая; защищает от реальных угроз — утечки бэкапа и утилизации диска у провайдера | компрометация живого сервера даёт доступ ко всему |
| Приложенческое шифрование приватных записей, `tsv` рядом | ощущение защищённости | **театр**: `tsvector` раскрывает содержимое. Хуже отсутствия шифрования, потому что на него полагаешься |
| Полное приложенческое шифрование, ключ вне сервера | настоящая защита от компрометации сервера | ключ надо вводить руками при каждом старте → нет автоподъёма → нет утренней сводки. Плюс полнотекстовый поиск умирает целиком |
| Всё локально, ничего наружу | приватность по построению | требует круглосуточно включённого Mac (нарушает принцип 10) или вдвое более дорогого сервера; качество на русском хуже |
| Приватных записей нет вовсе | простота | самое ценное просто не будет записано — а ради него система и строится |

## Решение

**Приложенческого шифрования нет.** Приватность определяется не криптографией, а границей: приватная запись никогда не покидает сервер.

**Что значит «приватная запись»:**

| | Приватная | Обычная |
|---|---|---|
| `tsv` (поиск по словам, триграммы) | есть | есть |
| `embedding` | **NULL** | есть |
| аннотации LLM | **нет** | есть |
| Notion | **никогда** | после Фазы 6 |
| всплывание старого | участвует | участвует |

**Где проверка.** В `core/llm`, `core/stt` и `integrations` — то есть в точках выхода наружу, а не в вызывающем коде. Инвариант 5: вызывающий код не обязан помнить о приватности, и не должен иметь возможности её обойти.

**Как помечается.** `/private on` — все следующие записи приватные до `/private off`; дефолт — не приватно; кнопка «сделать приватной» под подтверждением приёма — ретроактивно.

**Голос в приватном режиме не принимается.** Расшифровка идёт через внешний API, поэтому принять голосовое под пометкой «приватно» означало бы отправить его наружу. Бот отвечает «приватный режим — только текст». Исключений в инварианте 5 нет.

**Ретроактивная приватность разрешена, но честно.** При переводе записи в приватные удаляются `embedding` и аннотации, а бот прямо говорит, что уже уходило наружу: для текста — «текст уже отправлялся во внешнюю модель», для голосового — что наружу уходило ещё и аудио. Запрещать переход нельзя: человек не всегда понимает в момент записи, что записал.

**Защита данных на диске:** шифрование диска VPS + `pg_dump` в объектное хранилище, шифрованный ключом, который на сервере не лежит. Проверка восстановления — раз в месяц. Аудио не бэкапится и удаляется через 30 дней.

## Цена решения

- **Принимаемый риск, зафиксированный явно: компрометация живого сервера = доступ ко всему.** Диск расшифрован, пока машина работает; приватные записи лежат открытым текстом. Это главная цена, и платится она сознательно — ради автоподъёма и работающего поиска.
- **Приватные записи — второй сорт в ретривале.** Без эмбеддинга они находятся только по словам и триграммам, а семантический поиск их не видит. Самое личное ищется хуже всего.
- **Приватные записи не размечаются.** Ни типа, ни тем, ни связей, ни попадания в сводки — то есть для «умной» части системы их не существует.
- **Голосом приватное не записать.** Постоянное трение: именно то, что хочется наговорить не думая, придётся печатать. Альтернатива была хуже — приватность, протекающая в одном канале из двух, опаснее её отсутствия.
- **Ретроактивная приватность не отматывает назад.** Кнопка удаляет производное у нас, но текст уже был у провайдера. Честное сообщение — это всё, что можно предложить.
- **Гарантию даёт код, а не математика.** Ошибка в одной из трёх точек проверки ломает приватность молча. Отсюда обязанность: тест на «приватная запись не уходит наружу» — в быстрых unit-тестах, на каждом прогоне.
- Приложенческое шифрование не отменено навсегда: если изменится модель угроз, оно добавляется поверх — но тогда придётся заново решать вопрос ключа при старте.
